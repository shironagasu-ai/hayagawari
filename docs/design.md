# HAYAGAWARI 設計メモ

## ゴール

- イラスト複数枚 → スタイリッシュなモーショングラフィックで次々紹介するポートフォリオ映像
- 60fps でキビキビ、タメツメのはっきりした動き
- ランダム / プロシージャルな変化で、使う人ごとに違う成果物
- イラストの「目を引く箇所」を演出に使う

## 構成（1フレームの流れ）

1. 作品セグメントをオフスクリーン FBO に描く（背景色 → 背景装飾 → 振付 → 文字）
2. トランジション合成シェーダーでメイン FBO へ（ずらし＋方向ブラー / ズーム＋放射ブラー / アイリス / スライス / グリッチ）
3. オーバーレイ（カラーバー型トランジション、HUD）
4. ポスト（色収差・フラッシュ・シェイク・グレイン・ビネット）

セグメントは時間的に重ならない。トランジションは「出（〜0.34s、予備動作付き expoIn）」と「入り（〜0.52s、expoOut）」を
境界で速度最大のまま繋ぐ設計なので、2 シーンを同時に描く必要がない。

## ランダム化の軸（シードで決定）

| 軸 | 候補 |
|---|---|
| テーマ | NOIR / SWISS / POP / EDITORIAL / GLITCH / MONO / NEON / PASTEL / RETRO（背景モード・書体・グレイン・色収差・BPM 帯・各演出の重み）。「ミックス」は作品ごとに抽選（連続しない）し、オープニング/エンディング/HUD/BPM はベースのスタイル |
| BPM | テーマの帯域＋テンポ設定（1作品 = 6 / 8 / 10 拍） |
| オープニング | montage / type / shutter / countdown / knockout / slice（上下2段の寄りがすれ違い、名前の上下が噛み合う）/ tunnel（入れ子の額の奥へ吸い込まれる）/ boot（端末風の起動ログで作品を読み込む） |
| エンディング | grid / filmstrip / stack / knockout / orbit（楕円軌道を回って止まる）/ curtain（短冊の幕が上がると名前）/ rewind（逆順に加速して白く飛ぶ） |
| 振付 | focus（寄りで溜めて一気に引く）/ cuts（拍ごとの寄りカット→カラーブロック開示）/ split（分割パネル）/ pan（全面パン）/ card（カード＋残像＋虫眼鏡コールアウト）/ mosaic（注目点に近い順にタイルが集まりカチッと詰まる）/ spotlight（沈めた絵の注目点を照らし渡り、全開）/ triptych（3枚の短冊が溜めて合体）/ lockon（注目点を順にブラケットでロックオン） |
| 背景装飾 | 巨大番号 / 流れる袋文字 / グリッド＋トンボ / 作品のぼかし / 斜めストライプ / ドット |

| 配置・角度・ズーム量・方向 | 作品ごとに抽選 |

## 注目点（目を引く箇所）の検出

`src/analyze.js`。長辺 160px に縮小して以下を合成し、近傍抑制付きでピークを最大 4 点:

- 周波数同調型顕著性（平滑化 Lab と平均 Lab の距離）… 0.30
- ディテール密度（輝度勾配の局所平均）… 0.55 ← 目・手・装飾など描き込みの集中を拾う
- 彩度 … 0.15
- やや上寄りの中心バイアス

サンプルでは目・塔・同心円・看板・花芯を正しく拾う。外れたときは注目点エディタで直せる（移動・追加・削除・優先順・寄りの範囲。最大4点、1番が主役）。

注目点の使い道:

- focus: 注目点の超寄りで溜め → 引きでレイアウトへ着地
- cuts / opener: 拍ごとに注目点を切り替える寄りカット
- pan: 注目点 1 → 2 へタメツメのパン
- card: 注目点にリング＋引き出し線＋拡大円（虫眼鏡）
- mosaic: 注目点に近いタイルから組み上がる / spotlight: 注目点を照らす / lockon: 注目点を順に照準
- オープニング montage・shutter・countdown・knockout とエンディングの grid・knockout も注目点を中心に切り出す
- zoom / iris トランジション: 注目点に向かって吸い込まれる / 閉じる

## 書き出し

- `src/export.js`: t = i / fps の絵を描き、同じタスク内で `new VideoFrame(canvas)` に取り込んで `VideoEncoder` へ。出力チャンクを mp4-muxer で MP4 に（`fastStart: 'in-memory'` で moov を先頭に）
- エンコーダの待ち行列が 8 を超えたら `dequeue` を待つ（メモリ保護）。UI への制御返しは MessageChannel で行い、非表示タブのタイマー間引きを受けない
- 書き出し中はレンダラーを「仮想解像度 × 倍率」（4K は 2 倍）にし、終わったら画面サイズに戻す
- コーデックは H.264（High → Main → Baseline）→ VP9 → AV1 の順に `isConfigSupported` で判定。すべて不可なら MediaRecorder の実時間録画
- ビットレートは画素数 × fps から算出（1080p60 ≈ 16Mbps、4K60 ≈ 45Mbps）

### 音（`src/audio.js`）

- 楽譜 = film から作る「時刻付きの音の一覧」。ビート（キック / ハット / クラップ / ベース / プラック / レコードノイズ）と効果音（場面転換の種類ごとのスイープ、flash / shake イベントの一撃、細かいカットのクリック）
- 同じ合成関数を、プレビューでは AudioContext に 0.25 秒先まで先読み予約し、書き出しでは OfflineAudioContext で一括生成する
- プレビュー中は映像の時刻を音の時計に寄せる（ズレ 60ms 超は即座に、それ以下はなめらかに）。音の時計が進まない環境では従来どおり画面の時計で再生
- 出力段: コンプレッサー（-10dB・6:1）＋音量調整。ピーク約 0.65〜0.76 で割れない
- 書き出し: 音声を先に AudioEncoder でエンコード（AAC → Opus の順に判定）し、mp4-muxer の音声トラックへ

### コーデックとライセンス（2026-09 時点の調査。法的助言ではない）

- 本リポジトリにコーデックの実装は含まない。エンコードはブラウザ内蔵の WebCodecs（Chrome / Edge / Safari 等が自社のライセンスで提供）で行う
- H.264 の特許料は Via LA の AVC プールが扱い、対象は主に「エンコーダ/デコーダ製品の販売（年 10 万台まで無料）」と「有料配信」。無料のインターネット動画は無償（2010 年に期間中無償と表明）。12 分以下の作品単位の販売も無償
- 2026 年の配信料金改定は、新規にライセンスを受ける大規模配信・SNS 事業者向けで、個人の作品制作や端末内で完結する Web ツールは対象外と読める
- 米国の H.264 特許は 2027-11 に最後の 1 件が満了予定（他国は 2030 年まで残るものあり）
- VP9 / AV1 は Google / AOMedia が無償ライセンス。Sisvel のプールはハードウェア製品が対象で、コンテンツへの請求はしないと表明
- AAC も同様に、特許料の対象はエンコーダ / デコーダ製品の販売で、音声の配布（配信・放送・物理メディア）には料金がかからない。Opus は無償の規格
- 同梱の mp4-muxer は MIT（著作権表示とライセンス全文を vendor/ に保持）

## 文言のルール

- サブタイトル未入力なら何も出さない（PORTFOLIO 等を自動で補わない）。HUD 右上は「サブタイトル — 年」か年のみ
- 作家名が未入力のときだけ、名前の代わりに PORTFOLIO を出す

## 今後のアイデア

- アニメ顔・目の検出モデル（ONNX / WebGPU）で注目点の精度を上げる
- BGM を読み込み、BPM 検出（または手入力）でカットを曲に同期。書き出しに音声を含める
- 注目点の「形」を使った演出（顕著性マップをマスクにしたシルエット抜き・注目領域だけ色を残すなど）
- 作品ごとの手動オーバーライド（振付の固定・尺の延長）
