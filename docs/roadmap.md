## v1.1: BGM の持ち込み（統合ブランチ `release/v1.1.0`）

v1.0.0 では合成の音をなくした。v1.1 で、ユーザーが持ち込んだ曲に合わせて映像を作れるようにする。

3 段に分けて進める。各段の PR は `release/v1.1.0` 向けに作り、最後に `release/v1.1.0` → main の PR（版を 1.1.0 に上げる）でリリースする。

### (a) 曲の読み込みと BPM・拍・小節の頭の推定 … 実装済み（#19）

- `src/music.js`（解析。DOM を使わない純粋な関数）・`src/music-worker.js`（Worker の入口）・`src/song.js`（曲の欄の UI）
- 推定の流れ: 22.05kHz モノラル → spectral flux のオンセット → 自己相関でテンポ（120 BPM 付近を優先）→ 拍の山に直線を当てはめて間隔と位置を詰める → 倍・半分の取り違えを直す（間の拍と 1/4・3/4 の音で判定）→ 150Hz 以下のエネルギーと「曲の最初のはっきりした拍」で小節の頭
- 格子の形は `{ bpm, beat, first, bar }`（first = 最初の拍の秒、bar = 小節の頭が first から何拍目か 0..3）。`nextDownbeat(g, t)` で t 以降の小節の頭が取れる
- 手直し: BPM 入力・÷2/×2・タップ（T キー。推定に近い間隔なら推定の間隔を使い、位置と倍・半分だけ直す）・小節の頭 ← →・自動に戻す
- 曲と手直しは IndexedDB（`kv/"song"` に `{key, blob}`、設定は session の `song`）
- 未確認のこと:
  - **実際の曲での精度**（テストは合成ドラムのみ。22 通りで BPM ±0.01・拍 2ms 以内）。特に倍/半分と小節の頭
  - 倍/半分は本質的に曖昧（例: スネアの弱い 150 BPM は 75 にも聞こえる）。外れたら ÷2/×2 で直す前提
  - Safari（`webkitOfflineAudioContext`・module Worker の対応）

### (b) 映像を曲に合わせる・同期再生 … 実装済み

決めたこと（実装はこの節の下の当初の計画に沿う）:

- テンポ: 曲の BPM の ×1・÷2・×2 のうち、スタイルから抽選したテンポに log で最も近いもの（`fitTempo`）。抽選は曲があってもするので、演出の抽選結果は曲の有無で変わらない
- 作品あたりの拍数: 曲の小節（映像の拍で 4m 拍、m は上の倍率）の倍数で、曲がないときの 1 枚の秒数に最も近いもの。「きびきび」だけは半小節きざみ（小節単位だと「ふつう」と同じになりやすい）。最短 2.4 秒
- 曲の位置: 映像の t 秒 = 曲の `offset + t` 秒。`offset = nextDownbeat(grid, オープニングの長さ) - オープニングの長さ`（オープニング 6 拍の終わり＝最初の作品が小節の頭。曲の頭から 1 小節未満を飛ばす）。エンディング（8 拍）の最後の 2 拍でフェードアウト
- 曲が映像より短いとき（ユーザーに確認済み）: 作品の拍数を 1 単位ずつ減らして収める。最短でも収まらなければそのままで、曲が終わったあとは無音
- プレーヤー: 曲用の `<audio>`（試聴とは別）。映像の時計は rAF の経過時間で進め、曲の `currentTime - offset` と 40ms 以上ずれたら曲に合わせる（`musicTime`）。一時停止・シーク・前後の作品・ループ・再生中の作り直しで曲の位置を合わせ直す。実時間の録画中は曲を鳴らさない（(c) で扱う）
- 未確認のこと:
  - Bluetooth イヤホンなど出力の遅れが大きい環境でのずれ（`<audio>` の currentTime は出力の遅れを含まない）
  - iOS Safari は `audio.volume` を変えられないのでフェードアウトしない（書き出しでは (c) で波形にフェードをかける）
  - 実際の曲での聞こえ方（テストは合成ドラム）

当初の計画:


- 曲があるとき、映像のテンポ（`src/director.js` の `bpm` / `beat`。今はスタイルの `bpm` 範囲から抽選）を曲の格子の BPM にする。倍・半分のうち、スタイルの範囲に近い方を選ぶ
- 映像の 0 秒を曲の小節の頭に合わせる（曲の再生開始位置 = `nextDownbeat(grid, 開始したい位置)`。まずは曲の頭から最初の小節の頭）
- 映像の長さと曲の長さ: 映像が短ければ曲をフェードアウト、曲が短ければ最後で曲を終える（映像の尺は変えない）か、作品あたりの拍数を減らして曲に収めるかは要検討（ユーザーに確認）
- 作品の切り替え・カットは今も拍頭に置いているので、拍の間隔が曲と一致すれば自然に合う。小節の頭で作品が切り替わるよう、作品あたりの拍数を 4 の倍数に寄せる
- プレーヤー: 映像の時刻を曲の `<audio>` の `currentTime` に従わせる（今は `requestAnimationFrame` の経過時間）。シーク・一時停止・別バージョン・前後の作品へ移動で曲も合わせる。ずれが 40ms を超えたら映像側を合わせる
- 曲がないときは今までどおり（無音・スタイルの BPM）
- テスト: 合成ドラムを読み込んで映像の BPM が曲と一致すること、切り替えの時刻が拍に乗ること（±1 コマ）

### (c) 書き出しに曲を入れる・権利の注意書き … 実装済み

- 書き出すとき曲を 48kHz で読み直し（`songAudio`）、`cutSong` で映像の尺に切り出す（頭は 5ms で立ち上げ、最後の 2 拍でフェード、曲が短ければ残りは無音、2ch にそろえる）。`exportFrames({ audio })` で映像より先にエンコード
- コーデックは `pickAudioConfig`（AAC → Opus）。Opus のとき・音声を書き出せないときは書き出しの画面で知らせる
- 実時間の録画（WebCodecs が使えないブラウザ）では曲を入れない（対象のブラウザが少ないため見送り。画面で知らせる）
- 曲の欄に BETA の表示。曲の欄と書き出しの画面に権利の注意書き
- iPhone（Safari）で「書き出した動画に音が入らない」報告あり（原因は実機で未確定）。手当て: AAC は `format: 'aac'` を指定し、ADTS の見出しが付いていれば取り除く／エンコーダーが空の設定情報（description）を返したら muxer の推測値（AAC-LC）を使う／output の中の例外を拾って失敗にし、音声が 0 件なら失敗にする／書き出し後に `audioPlayable` で音声を読み戻し、再生できなければ知らせる
  - 続報: iPhone 17 Pro の Safari で「音声: AAC」なのに書き出し後の確認で再生できず、音声なし。Apple の AAC エンコーダーは設定情報を AudioSpecificConfig ではなく ES_Descriptor（esds の中身）で返すと推測し、`aacSpecificConfig` で中の AudioSpecificConfig を取り出すようにした（未確認）。再生できないときは書き出しの画面に診断（設定情報の先頭・取り出した値・件数・バイト数・先頭のバイト）を出す
- AAC は OS のエンコーダーを使うので、Linux の Chrome（CI の Chrome も）では使えず Opus になる。AAC の経路は CI では通らない
- 未確認のこと: 長い曲をスマホで書き出すときのメモリ（曲全体を 48kHz・float で読むので 4 分で約 90MB）。Mac・Windows の Chrome / Edge と Safari で AAC になるか（実機で確かめる）
